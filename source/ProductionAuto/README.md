# 链式自动化 Mod（ProductionAuto v1.1.0）

## 这是什么

把箱子放在加工机械隔壁，自动完成**投料 → 加工 → 取料**全流程，无需按键、无需面板。

- **纯位置驱动**：箱子放在加工机械隔壁时自动连接，双子箱一进一出，单箱子本箱内一进一出
- **链式自动化**：A箱→机器→B箱→机器→C箱，可无限串联，实现全自动生产线
- **14种机器全覆盖**：榨汁机、酿造桶、酸奶机、腌制桶、烟熏机、干燥机、蜂箱、蚕盒等（共28个机器变体，932条配方）
- **智能投料**：检测机器空闲槽位和原料可用性，自动投料
- **自动取料**：加工完成后自动转移到输出箱子，不阻塞后续生产
- **防卡顿**：事件驱动 + 时间预算 + 分批扫描，每帧开销极低
- 支持双子箱（输入箱/输出箱分离）和单箱子（本箱一进一出）两种模式

## 安装

本 Mod 通过游戏根目录的 `steam_api64.dll` 桥接基座加载，与其它 Mod 共存。

1. 关闭游戏；
2. 把整个 `ProductionAuto_v1.1.0` 文件夹放入游戏根目录的 `Mods` 文件夹；
3. 确认游戏根目录已有桥接基座（`steam_api64.dll` + `steam_api64.org.dll`）；
4. 直接从 Steam 启动游戏。

## 使用

### 基本用法

1. 把一个箱子放在加工机械旁边（相邻一格内）；
2. 箱子会自动检测到隔壁的机器并建立绑定；
3. 往箱子里放入原料，机器会自动取料加工；
4. 加工完成后产物自动放回箱子。

### 双箱模式（推荐）

在机器两侧各放一个箱子：
- 一个做**输入箱**（放原料）
- 一个做**输出箱**（收成品）
- 机器自动从输入箱取料，加工后放入输出箱

### 链式自动化

把多个机器+箱子串联摆放：
```
输入箱 → 榨汁机 → 中间箱 → 酿造桶 → 输出箱
```
中间箱既是前一个机器的输出箱，又是后一个机器的输入箱，实现全自动流水线。

### F3 控制面板

按键盘 **F3** 打开控制面板，可查看：
- 所有活跃绑定的状态（运行中/等待投料/产出就绪等）
- 每台机器的当前配方和进度
- 手动暂停/恢复某个绑定

再按 F3 关闭面板。

### F5 诊断 HUD

按键盘 **F5** 打开诊断 HUD，可实时查看调度器状态和绑定详情。再按 F5 关闭。

生产链条较多时，HUD 高度会自动限制在屏幕内，超出部分可滚动查看：

| 输入方式 | 操作 |
|----------|------|
| 手柄 | 十字键上/下 = 逐条滚动；LB/RB = 翻页；左/右摇杆 Y 轴 = 连续滚动 |
| 键盘 | ↑/↓ = 逐条滚动；PageUp/PageDown = 翻页 |

## 调试日志开关

发布版默认禁用所有日志输出，不生成 `qol_productionauto.log`。

如需开启日志（排查问题、适配新版本等），需重新编译：

1. 在 `ProductionAuto.vcxproj` 的 `PreprocessorDefinitions` 中添加 `PRODUCTIONAUTO_LOGGING`；
2. 重新编译（Release x64），部署 DLL 到游戏 `Mods` 目录；
3. 启动游戏后操作，日志写入游戏根目录 `qol_productionauto.log`（加密格式，每次启动清空旧日志）。

调试完毕后移除 `PRODUCTIONAUTO_LOGGING`，重新编译恢复无日志模式。

## 适配新游戏版本

游戏更新后本 Mod 可能失效。以下情况需要重新定位地址：

| 地址类型 | 适配方式 | 工具 |
|----------|----------|------|
| AOB 签名函数 | 自动适配（字节签名扫描） | 无需操作 |
| 硬编码 RVA | 需重新定位 | `aob_scanner.ps1` + IDA/Ghidra |
| 配方表 | 重新生成 | `recipe_gen.exe` / `recipe_scan` |

适配流程：

1. 开启调试日志，启动游戏；
2. 查看 `qol_productionauto.log`，检查 AOB 扫描结果；
3. 如果 AOB OK 但功能异常，说明 RVA 需更新；
4. 用 `aob_scanner.ps1` 重新扫描 AOB 签名定位函数地址；
5. 签名 0 匹配或 RTTI 地址需用 IDA/Ghidra 人工提取；
6. 更新 `version_manifest.h`；
7. 如配方表也变化，运行 `recipe_gen.exe` 重新生成 `processing_recipe_table.inl`；
8. 重新编译部署。

## 技术架构（供 Mod 作者参考）

### 调度器设计

| 组件 | 说明 |
|------|------|
| Binding（绑定） | 一个箱子-机器连接，含输入/输出/状态/调度信息 |
| Flood-fill（泛洪连接） | 自动检测相邻箱子-机器关系，支持链式串联 |
| Scheduler（调度器） | 按游戏时间调度绑定评估，事件驱动+时间预算 |
| Dirty/Parked 机制 | 绑定状态变更时标记Dirty重新评估，空闲时Parked节省开销 |
| Output Priority | 产出转移优先于投料，防止机器满载阻塞 |

### 关键函数调用链

```
mod_init  → AOB 扫描定位引擎函数
           → 加载存档配置（config_load）
           → 初始化 F3 面板和 F5 HUD

mod_tick  → ProductionRefreshScheduler（每帧调度入口）
             → ProductionSelectDueBinding（选择到期绑定）
                → ProductionEvaluateBinding（评估绑定状态）
                   → WaitingInput → ProductionAttemptInput（投料）
                   → OutputReady → ProductionTransferOutput（取料）
                → ProductionScheduleBindingFromSnapshot（安排下次调度）
```

### 安全措施

- 所有指针访问前 `IsReadable` 检查（含区域缓存加速）
- 投料前：配方匹配 + 容量校验 + 原料数量验证
- 取料后：数量一致性验证 + 引用计数管理
- 全程 SEH 保护，异常立即停止
- 暂停状态下 drain-on-pause：仅允许产出转移，不启动新生产

### 性能优化

| 优化点 | 说明 |
|--------|------|
| 事件驱动调度 | 绑定只在状态变更时重新评估，非每帧轮询 |
| 时间预算 | 每帧限定处理绑定的数量，防止卡顿 |
| 分批扫描 | 泛洪连接和箱子注册表增量更新 |
| 区域缓存 | VirtualQuery 结果缓存，减少系统调用 |
| 双缓冲 HUD | F5 面板双缓冲绘制，消除闪屏 |
| HUD 缓存 | 窗口尺寸未变时跳过圆角重建/SetWindowPos；DC/Bitmap 按尺寸复用；异步重绘避免同步阻塞游戏 tick |
